# 风车笔记 / pinwheel 安全复查

日期：2026-10-26。基线：桌面 0.10.1；修复后源码：桌面 0.10.2、鸿蒙 0.2.2。

更新（2026-10-27）：已经重新构建 0.10.2 发行文件，并完成新 Windows 程序和安装器回归，见 [0.10.2 发布构建验证](RELEASE-0.10.2.md)。以下保留 2026-10-26 复查时点的发现与验证范围；不能用旧 0.10.1 文件代替本次新构建。

**结论：发现需要修复的问题，已经修改源码并执行回归。不能据此认定软件没有安全问题。此前生成的 0.10.1 安装包、便携包、Mac 包和 GitHub-ready 包均不包含本次修复；此前鸿蒙 0.2.1 源码包也不包含。** 本目录报告对应当前源码，不是旧包的安全背书。

## 范围和方法

人工检查 Electron 窗口、preload/IPC、系统打开接口、文件访问授权、附件目录、笔记包和宠物包、Markdown/公式/Mermaid、主题配置、加密与恢复流程、鸿蒙原生桥及 Web 存储。以合成文件验证隐藏文件导出、NTFS 目录链接、重复 ZIP 名称、虚报解压大小、图片尺寸、恶意渲染内容及真实窗口授权。所有桌面测试使用独立笔记和配置；没有读取真实笔记，没有运行恶意附件。

锁文件中的公开依赖名与版本提交到 npm 官方漏洞接口；同时核对上游安全公告。未上传笔记、源码或密钥。审查没有覆盖每一条依赖源码、Chromium 所有内部组件、操作系统、任意第三方查看器或未知漏洞。

## 发现与修复

下列等级是本次应用场景判断，不是官方 CVSS 评级；成立条件和证据分别说明。

| 项目 | 判断与成立条件 | 修复与验证 |
| --- | --- | --- |
| 隐藏文件被笔记包收集 | 高风险信息泄露。笔记含 `.env` 等附件链接且用户导出笔记包时，旧实现可读取笔记库内隐藏文件。已用仅含模拟标记的 `.env` 复现；未读取真实凭据。 | 拒绝隐含授权范围内的隐藏文件、目录及 `.notebook`；检查词法路径和实际路径，阻断可见链接指向隐藏目标。明确选择的隐藏附件根目录仍可用。导出与真实资源协议测试通过。 |
| 附件打开依赖不完整的扩展名黑名单 | 高风险执行入口。旧代码让 `.hta`、`.cpl`、`.command`、`.sh`、`.desktop` 等进入系统默认打开接口；实际执行取决于平台、文件关联、文件内容及用户点击。这里只确认代码路径，没有启动恶意程序或复现系统执行。 | 改为有限的文档、图像、影音类型允许列表。HTML、SVG、可执行与未知类型仅在文件管理器定位。真实 Electron 测试替换系统打开函数，确认脚本类型没有进入 `openPath`。允许列表不保证文件内容或外部查看器无漏洞。 |
| 压缩包与大文件资源边界不足 | 中风险拒绝服务。旧流程部分限制在 JSZip 建立条目对象之后执行，且解压前主要信任声明大小，读取文件也存在先载入再检查的路径。没有实际耗尽机器内存。 | JSZip 前预检中央目录、数量、名称、重叠数据、链接、文件头和大小；解压时累计实际输出并限量保留，检查声明大小、清单范围和 SHA-256。文件在 stat、打开后和分块读取过程中均限量。笔记包、宠物包及鸿蒙导入共用检查。重复名称与虚报大小夹具被拒绝。 |
| 目录链接扩大授权或替换内部存储 | 中风险，需预置或修改本机笔记目录中的链接。原有只检查“属于某个实际根目录”的逻辑不足以区分默认附件目录和显式授权外部目录。 | 授权绑定词法根和实际根；库内附件根不能借链接跨出库；内部目录逐层拒绝链接，内部文件拒绝链接及特殊文件。真实 NTFS junction 测试通过。不能完全抵御同权限本地进程并发替换路径的竞态。 |
| 间接 KaTeX 旧版本 | 上游评级 Low。原 `rehype-katex` 和 `micromark-extension-math` 路径带入 0.16.47，命中 GHSA-238p-pmpm-9mq7。公告要求事先存在原型污染等前置条件；本应用没有复现该完整利用链。Mermaid 的 0.18.10 不在此公告受影响范围。 | npm override 将全部 KaTeX 解析到直接锁定的 0.19.0。更新锁文件与第三方许可清单。当前官方漏洞接口结果为空，公式和 Mermaid 正常渲染。 |
| 图片在尺寸检查前进入原生解码器 | 资源消耗防御加固，未确认原生解码器漏洞。旧宠物图片流程先创建原生 bitmap，再看尺寸。 | 使用 `image-size` 只读头部，在原生解码前限制 4096×4096、10MiB；GIF 另限制帧数和累计像素。尺寸夹具、GIF 容器、正常宠物导入、绘图、动作包及重启恢复回归通过。普通笔记图片仍由浏览器解码，不能保证所有图像的固定 CPU/内存预算。 |
| IPC 与窗口导航边界 | 纵深加固。旧实现已校验窗口和主 frame，但没有绑定精确应用 URL；未证明可据此单独实现攻击。 | 主窗口和宠物窗口分别校验窗口、主 frame、精确 file URL 与角色参数；禁新窗口、导航、跳转、webview和权限申请；CSP 禁止 frame/object/base/form。真实窗口改动 URL 查询参数后 IPC 被拒绝，恢复 URL 后正常。 |

`baseline.json` 保留旧版合成复现与扩展名分类结果。上游公告说明见 [KaTeX 官方安全公告](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7)；该公告不表示 KaTeX 自己产生原型污染。窗口加固参考 [Electron 官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。

压缩包流读取在超限后停止保留输出并暂停流；正在处理的压缩块可能继续计算。它不能被描述为完整的 CPU 隔离或对所有压缩算法攻击的证明。

## 加密检查与剩余边界

未发现这轮测试中的明文落盘回归：正文、历史和恢复记录在文档加密后均受保护，认证失败不返回明文。现有格式采用 AES-256-GCM、随机盐/IV、固定参数 scrypt 与认证附加数据，密码不写入设置。此次没有自行更换密码算法或破坏旧格式。

但以下边界仍存在：

1. 用户要求只加密正文，因此文件名、图片和附件不加密。密码强度由用户选择；弱密码仍可能被离线猜测。
2. 编辑时明文进入内存；JavaScript 字符串、操作系统交换区、崩溃转储和系统备份不保证安全擦除。锁定密钥缓冲不等于消除所有内存副本。
3. 有效旧密文可以被回滚，本格式没有版本防回滚认证。外部查看器、显式授权附件内容及本机同权限恶意进程不在完整防护承诺内。
4. 复杂 Markdown、公式、Mermaid 和图像可能消耗大量计算资源；没有完整模糊测试、硬 CPU 超时隔离、沙箱逃逸验证或供应链源码全面审计。
5. 主界面仍使用 file URL，已限制导航并绑定 IPC；Electron 建议优先使用自定义协议，后续可继续迁移。没有因此宣称已满足所有上游安全建议。
6. 无 macOS 实机测试、Apple 开发者签名/公证；本次没有重新验证 0.10.2 Windows 安装器。源码包的 SHA-256 用于检查文件一致性，不等于发布者签名。

本报告是有范围限制的代码复查与回归证据，不是渗透测试认证，也不改变此前名称/商标和开源许可审计的保留事项。发布时应使用包含本次修复的新构建，不应继续把旧 0.10.1 准备包当作本次修复版。
